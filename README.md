# Снежок — Android 0.18

Текущая копия включает Android 0.18 и ресурсы темы HONOR 6.0.7. Для сборки см. [BUILD.md](BUILD.md). Заметки ниже относятся к ранним версиям.

Оригинальное локальное приложение для декоративного снега поверх обычных Android-приложений. По мотивам идеи Snowhush, без копирования кода или ресурсов Snowhush.

Снегопад, накопление и таяние сугробов у нижней границы, ёлочка с огоньками, регулировка интенсивности и высоты, бережный режим24fps, уведомление с остановкой/очисткой и плитка быстрых настроек. Без сети, рекламы, Accessibility, считывания экрана и root. При выключенном экране пауза; для заблокированного экрана добавлен отдельный режим живых обоев. Автозапуска overlay после перезагрузки нет; выбранные живые обои запускает сама система.

## Изменения 0.6

- По прямому поручению владельца изменено только имя WallpaperService в системном списке на «Я · Снежок — живые обои». Буква Я должна переместить строку после «Темы» при русской сортировке, вместо непредсказуемой сортировки эмодзи. Порядок на самом Honor ещё не проверен; component/package/основное имя приложения сохраняются.
- Реальная native-анимация в WallpaperService: усилены пульсации огней ёлки, добавлены пульсации лампочек фоновой гирлянды, а не только падающий снег поверх картинки.
- Реалистичная белочка с четырьмя позами из нового собственного built-in imagegen RGBA sprite-sheet. Паузы на восьми ветках, параболические прыжки между ними, разворот по направлению, небольшие повороты/сжатие при посадке. Весь цикл рисуется Canvas в реальном времени; это не видеопетля. Настройка «Белочка прыгает по ёлке» отключает её отдельно.
- Общий ограниченный atlas без копирования для каждого Engine; четыре позы выбираются по реальным размерам листа1254×1254. Цветной скрытый RGB вокруг шерсти находится только в пикселях alpha1–2/255; root отдельно подтвердил отсутствие таких пикселей с alpha>2, Android использует нормальное premultiplied compositing. PNG не редактировался после генерации. Промпт/источник в art/SQUIRREL-PROMPT.md.
- Когда включена белочка, сцена получает20/30fps даже без снегопада. Только гирлянды/огни —8fps, только часы —1fps. Существующие паузы при OFF/DOZE/скрытии сохранены; расход батареи не измерялся.
- Изменение позиции строки списка НЕ является исправлением назначения живого компонента на lockscreen. Проверка пути через перемещённую строку остаётся действием владельца; ранее подтверждённый direct-home-only результат не переименовывается в успех lock.

## Изменения 0.5

- Перед системным выбором обоев/списком/страницей настроек собственного приложения слой SYSTEM_ALERT_WINDOW синхронно снимается через same-process main-thread controller. View и накопленные сугробы сохраняются. На паузе display/receiver/reconcile не возвращают слой поверх защищённого окна.
- После результата системного окна пауза снимается только её владельцем. Если пользователь выключил службу уведомлением/плиткой, возврат не запускает её заново. Состояние владения паузой сохраняется при пересоздании Activity; вложенное окно не присваивает чужую паузу. При выходе через «Домой» без результата есть явная кнопка «Продолжить снег» в приложении.
- Это соблюдает системные проверки нажатий при наложениях, а не ослабляет их. Точная причина недоступности пункта в списке Honor без проверки на телефоне не объявляется доказанной.
- На снимке владельца системный список размещает первую строку под своей верхней панелью. Разметка чужого системного приложения не меняется; прямая кнопка «Выбрать живые обои „Снежок“» позволяет не пользоваться этим списком. Диагностика фактического назначения home/lock из0.4 сохраняется. Установка live wallpaper на lock Honor пока остаётся нерешённой.

## Изменения 0.4

- Выбор home/lock сцены по реальному `WallpaperService.Engine.getWallpaperFlags()` на Android14+: home-only Engine всегда использует home-настройки, lock-only всегда lock-настройки. Только общий Engine обоих экранов использует состояние keyguard. Это убирает ошибочное заимствование lock-ёлки домашними обоями на переходе разблокировки. Не является подтверждением установки живых обоев на lock конкретного Honor.
- Добавлена обработка изменения назначения через `onWallpaperFlagsChanged`.
- В приложении показана проверка собственных назначений по `WallpaperManager.getWallpaperInfo(FLAG_SYSTEM/FLAG_LOCK)`, отдельная кнопка обновления и автоматическое обновление при возвращении в приложение. Запрашиваются только метаданные типа обоев, изображения и содержимое экрана не читаются. Сравнивается только собственный ComponentName, имена других приложений не выводятся/не сохраняются. `null` честно обозначен как «Снежок не подтверждён (обычные обои или данные недоступны)», а не доказательство отсутствия назначения.
- В manifest добавлен узкий queries intent WallpaperService по требованию API, без QUERY_ALL_PACKAGES и новых uses-permission. Обычное приложение не может принудительно вызвать системный setter живого компонента для lock в обход системного выбора.
- Добавлен запуск системного списка Android живых обоев отдельно от Photos «Живое фото». Никакие прежние обои/темы не очищаются. Сохранённые owner-настройки не сбрасываются.

## Изменения 0.3

- Большая фотореалистичная ёлка со стеклянными игрушками, звездой, подарками и огнями; отдельный детальный зимний фон с гирляндами. Два исходных raster asset созданы встроенным imagegen, просмотрены и сохранены в `art/`; prompts/метаданные в `art/PROMPTS.md`. В приложении неизменённые PNG в `res/drawable-nodpi/`, общая ограниченная bitmap-cache без чтения пользовательских фото/обоев.
- Плавное мерцание огоньков и снег поверх большой сцены. Ёлка центрирована, занимает около трёх четвертей высоты с учётом ограничения ширины, масштаб регулируется. В миниатюрном overlay-режиме используется та же подробная растровая ёлка; прежний вектор остаётся только резервом при ошибке декодирования.
- Кнопка «Ёлочка только на блокировке» отключает её в overlay и на домашнем wallpaper, включает на lock wallpaper. Все переключатели независимы: снег/ёлка на рабочем столе, снег/ёлка на блокировке, ёлка поверх приложений, гирлянды/фон.
- Необязательные золотистые часы на блокировке с живым временем, длинной датой и настройкой положения. По умолчанию выключены: они не заменяют штатный циферблат MagicOS, который может остаться видимым. Отключение системных часов не выполняется и не обещается.
- Новый живой предпросмотр именно lock-сцены в настройках, без захвата экрана и без эмуляции системного lockscreen. Реальная композиция зависит от размещения системных часов/уведомлений Honor.
- Автоуборка: при достижении заданной высоты сугроб постепенно опускается по новому случайному гладкому профилю, затем снова накапливается. Во время оседания новые снежинки продолжают падать, но не добавляются к сугробу. Ползунок «Скорость автоуборки» 0..100, 0 отключает цикл. Прежний ползунок высоты определяет порог; резкого сброса массы на начало/конец фазы нет.
- Старые APK/подпись сохраняются, установка обновлением поверх предыдущей версии. Возможности MagicOS по назначению живых обоев на экран блокировки требуют фактической проверки владельцем.

## Изменения 0.2

- Исправлен белый квадрат QuickSettings: отдельная прозрачная снежинка в manifest и явное обновление tile icon.
- Слой overlay восстанавливает свою Surface после сна; добавлены DisplayManager callbacks и сверка состояния при включённом экране, чтобы не зависеть только от USER_PRESENT. При выключенном экране polling и кадры прекращаются. Это исправление по коду, реальное повторное lock/unlock на Honor ещё требует подтверждения владельца.
- Overlay занимает весь экран без нижнего navigation inset; сугробы привязаны к физическому нижнему краю. Системная навигация остаётся выше overlay; её поведение зависит от оформления MagicOS.
- Отдельные настройки ёлочки поверх приложений и на живых обоях. Для home-only выключить первую, включить вторую и подтвердить установку живых обоев на рабочий стол. Нет UsageStats/Accessibility и определения активного приложения.
- Экран блокировки обслуживается штатным WallpaperService. Пользователь должен сам выбрать живые обои «Снежок» в системном диалоге и, если MagicOS предлагает, применить к экрану блокировки. Обои заменяют текущий фон собственным зимним фоном только после подтверждения. Мы не читаем и не копируем старые обои и не обходим защиту keyguard. Конкретная возможность live wallpaper на lockscreen Honor пока не проверена.
- Во избежание двойного эффекта wallpaper не рисует снег/ёлочку, если соответствующий эффект уже обеспечивает overlay на разблокированном домашнем экране. Preview живых обоев показывает их полный вид.
- Выключение overlay не удаляет выбранные живые обои. Их можно отключить в системных настройках обоев; настройки «Снег/Ёлочка на живых обоях» управляют эффектами отдельно.

## Установка

### Отдельный видеовариант для Gallery Honor

После проверки владельцем прямой установки выяснилось: на его текущей MagicOS APK применяется только к home, прежняя lock-картинка остаётся. Это согласуется с обсуждением ограничения сторонних компонентов на официальном форуме Honor, но не доказывает запрет на всех моделях/версиях.

В `exports/Snezhok-lock-video-01.mp4` подготовлен отдельный записанный видеоролик10секунд,1080×2400,H264,24fps, без аудио и записанных часов. Ёлка и фон взяты из собственных assets, снег/огни анимированы. Это видеопетля, не полноценный интерактивный WallpaperService: настройки приложения, текущие часы и новые случайные циклы сугробов на воспроизведение файла не влияют. APK0.5/настройки не заменялись. Проверены ffprobe и полное декодирование, кадр визуально просмотрен; реальная установка на lock Honor пока не проверена.

По [инструкции MagicOS10](https://www.honor.com/cn/support/content/zh-cn15886225/) некоторые модели поддерживают Live-фото/видео в lock. Владелец может сохранить MP4, открыть в Галерее и проверить меню установки как обоев/блокировки. Наличие этого пункта на конкретной прошивке не обещается; без него не выдавать ролик за рабочий обход. Часы остаются штатными MagicOS.

### APK

Установить APK, открыть «Снежок», нажать «Включить снег», выдать системное разрешение «Поверх других приложений» и вернуться. Разрешить уведомления для удобного выключения. Кнопка «Добавить кнопку в шторку» добавляет быстрый переключатель с подтверждением Android. Если MagicOS завершает приложение в фоне, открыть настройки приложения и разрешить фоновую работу/настроить управление запуском. Конкретный путь в MagicOS требует проверки на телефоне.

## Ограничения

- Target Android16/API36, минимальная версия Android8/API26. Реальный Honor Magic8 Pro пока не подключался; работа, расход батареи и жесты на нём не проверены.
- Overlay имеет FLAG_NOT_TOUCHABLE и FLAG_NOT_FOCUSABLE; оконная прозрачность ниже системного лимита пропуска касаний. Суммарная непрозрачность с другими одновременно включёнными наложениями может привести к блокировке касаний со стороны Android. При таком поведении выключить другие наложения или «Снежок» из уведомления/шторки.
- Клавиатура и системные панели выше приложения. Банковские и другие защищённые приложения могут скрывать снег или отклонять нажатия при наложениях — это политика приложений; обход не выполняется.
- Сугробы не распознают кнопки и иконки других приложений. Анимация находится в своём прозрачном слое, весь экран не считывается.
- Оверлей не перехватывает касания: управление ёлочкой/сугробами только через настройки. Нет взаимодействия пальцем поверх чужих приложений.
- FGS specialUse используется для явно включённого пользователем видимого украшения; после остановки системой запуск вручную. Эмуляция типа media/dataSync и обход ограничений фонового запуска не используются. Публикация в GooglePlay потребовала бы отдельной проверки политик и review типа сервиса, она не выполняется.

## Сборка

`bash build.sh` использует существующие JDK17 и AndroidSDK36 по пути из `ANDROID_SDK_ROOT` или `ANDROID_HOME`, без загрузки зависимостей/установки пакетов. Каждая сборка в новом каталоге build/vVERSION-XXXXXXXX; прежние артефакты сохраняются. Компиляция aapt2/javac/d8, выравнивание и подпись apksigner. Ключ локальной debug-подписи в `.signing/`, не отправлять; он нужен для последующих обновлений APK. Пароль стандартный development `android`, это не production signing setup. APK предназначен для прямой установки владельцем.
